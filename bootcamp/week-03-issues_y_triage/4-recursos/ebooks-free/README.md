## Qué leer si solo tienes una hora

**Producing Open Source Software, capítulo 3**, la sección de *Bug Tracker*.
Explica por qué un sistema de issues necesita estados, quién los mueve y qué
pasa cuando nadie hace triage. Está escrito antes de que GitHub existiera y
sigue describiendo exactamente tu problema.
